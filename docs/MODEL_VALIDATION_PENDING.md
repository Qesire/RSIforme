# 真实模型研究验收：审批阻断，保持待验证

记录日期：2026-11-27。对应 [参考工程验收](REFERENCE_PARITY.md) 的 G3/P0：至少两轮真实编码模型调用，第二轮实际消费第一轮固定评价的反馈。

## 本轮发生了什么

本机已检查 `codex-cli 0.172.0-alpha.2` 及 `codex exec --help`，并实现结构化 argv、stdin handoff、JSON schema、提案输出、日志、超时和持久状态。一次实际 `research-run` 曾写入 `worker_running` 与 PID，后续轮询或继续执行的操作被**自动审批审查拒绝**。审查给出的理由是：调用会向当前配置的 `ab.chatgpt.com` 服务入口传输本地上下文，而这一传输缺少明确授权。

因此，本轮没有取得可采纳的真实模型结果或两轮记录。已有进程标识和空日志不能证明是否曾发生网络请求，本文不作该断言。拒绝之后没有通过重试、替换客户端、变更端点或改用权限参数继续。该阻断不构成算法失败或错误提案的证据，也不能被计作一次完成的模型实验。

代码与本地协议验证继续按已有授权完成。scripted worker 的候选来自预写 fixture，`model_calls=0`，只验证控制器的真实状态转移、评价与交付。它是单独标记的工程验证，不替代被阻断的真实模型验收，也不关闭 G3/P0。

这份记录说明需要批准的具体工作，不构成授权本身。只有所需明确授权落实且执行环境允许后，才可在一个新研究归档中启动以下验收；当前协作不再次触发该被拒绝操作。

## 获准后使用的调用协议

argv 来自 [research.codex.example.json](../configs/research.codex.example.json)：

```json
["codex", "exec", "--sandbox", "workspace-write", "--skip-git-repo-check", "--json", "--output-schema", "{schema}", "--output-last-message", "{proposal}", "-"]
```

模板不覆盖模型，也不使用绕过审批或沙箱的参数。模型与身份配置沿用已获准的执行环境；真实使用的工具与模型身份以可观察运行记录为准。用户授权和工具是否允许执行仍是后续运行的必要条件，不能由本文件或一个成功的本地 scripted run 代替。

## 关闭待验证项所需证据

1. **冻结起点。** 在新归档中保存公开 baseline、完整固定评价、实际 profile、任务上下文与预算。worker 工作区只提供其父代和任务所需材料，不把预写 optimized/incorrect fixture 作为待发现答案。
2. **两轮真实调用。** 保存实际 argv、输入、日志、提案与进程状态。第一轮产物接受固定 evaluator；第二轮 handoff 包含其真实结果，并在提案或修改中指出消费了哪条反馈。
3. **可核对的状态与预算。** 记录源码、候选、父代、执行和评价的对应关系；失败、无改动、未知执行和停止均如实计入。需要恢复时使用已有记录，不重复提交。
4. **新的独立确认。** 从归档恢复选中源码，以新的执行身份完成确认；确认失败时保留失败和旧发布。没有改善也是有效的研究结果，不改写成性能收益。
5. **可交付结果。** 导出已晋升结果，核对摘要和原始证据；如果额外执行 portable reproduction，独立保存其新记录。研究计划、基线、profile、失败历史和预算摘要一同提供索引。
6. **声明与证据一致。** 将真实模型记录与 scripted fixture、原生 Harness、目标 GPU 的证据分开。满足上述条件只关闭这个有限 CPU 研究循环的真实 worker 验收，不证明自动生成新研究线、合并 winning branches 或普遍递归提升研究能力。
